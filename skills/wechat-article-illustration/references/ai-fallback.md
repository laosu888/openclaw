# AI Fallback

当真实图不足，或真实图无法表达文章核心时，才启用 AI 生图。

## 文章里可直接照抄的思路

参考文章里的路线，AI 生图是**单独一层能力**，不是默认主流程：

- 先完成文章配图判断
- 真实图搜索优先
- 若真实图不足，再调用 AI 生图
- AI 图优先补**封面**，其次才是正文补位图

## 推荐默认接法

先兼容“单独的 AI 生图供应商 + API Key 配置”的思路。

可以把 skill 默认支持的 AI 图提供方定义为：

### 方案 A：豆包 / 文生图接口
适合照着文章里的思路直接落地。

建议配置项：

```json
{
  "image_provider": "doubao",
  "doubao_api_key": "YOUR_KEY"
}
```

注意：不同版本文章/教程里，常会把“豆包生图”“文心接口”“火山/百度平台”写得比较混，真正落地时要以**当前可调用的官方接口文档**为准，不照抄过期 endpoint。

### 方案 B：本地已安装的 AI 生图 skill
如果当前 OpenClaw 环境里已经装了成熟生图 skill，则优先复用，不重复造轮子。

例如：
- `seedream`
- `ai-image-generation`

这种情况下，`wechat-article-illustration` 只负责判断“要不要生图”，不自己重新实现完整生图逻辑。

## API Key 规则

如果调用 AI 生图，必须显式说明需要用户提供相应 API Key。

### 最低要求
- 如果使用豆包：需要 `doubao_api_key`
- 如果使用其他生图服务：需要对应服务的 API Key

### 对用户的表达方式
当真实图不足且需要启用 AI 图时，明确告诉用户：

- 将使用哪一个 AI 图服务
- 需要填写哪个 API Key
- 这个 Key 用于封面 / 补图生成

不要默认假设用户已经配置好。

## AI 图生成策略

### 封面图
优先生成一张传播感更强、但不浮夸的封面图。

提示词原则：
- 围绕文章主题
- 风格统一
- 横版
- 避免复杂文字
- 不要生成明显低质“AI 感”画面

### 正文图
只补最缺的 1-2 张，不要一口气全篇都变成 AI 图。

提示词原则：
- 服务段落核心观点
- 以示意 / 概念 / 氛围图为主
- 避免替代真实信息图

## 启用 AI 图前的最终判断

启用前再过一遍：

- 这篇是不是已经有足够真实图？
- AI 图会不会削弱可信感？
- 这篇是不是教程文或项目解析文？如果是，AI 图只能极少量使用。
- AI 图是补封面，还是补正文？默认先补封面。

## 最重要的一句

**AI 生图是兜底能力，不是默认能力。**
